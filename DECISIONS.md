# Decisions

Choices made while building Paisa Pulse, with the reasoning, so they can be revisited.

## D1. Version policy: "latest stable, nothing released in the last 14 days"

- Cutoff for Phase 1 was **2026-10-10** (build date 2026-10-24).
- **Exception: Expo SDK patch releases.** `expo-doctor` (a required check) insists on
  the newest patch of every SDK package (e.g. `expo` 57.0.31, released 2026-10-21). The
  only way to keep older patches is `expo.install.exclude`, which silences the check.
  Patch releases inside an SDK that has been stable for four months are bug fixes, so we
  take them. Majors and minors of everything, and all non-Expo libraries, still follow
  the 14-day rule.
  _To revert:_ pin older patches and add them to `expo.install.exclude` in
  `apps/mobile/package.json` (doctor will then skip them).

## D2. Expo SDK 57, not 58

SDK 58.0.0 shipped 2026-09-29, but it targets React Native 0.88, whose stable 0.88.0
release is from 2026-10-15 (9 days old). Every SDK 58 patch before the cutoff bundles
`react-native@0.88.0-rc.x`, a release candidate. Running SDK 58 therefore means either
a pre-release or a too-new release. **SDK 57 (React Native 0.86.3, React 19.2.3)**
satisfies both rules. Upgrade to SDK 58 once RN 0.88.0 is older than 14 days
(on or after 2026-10-29): `npx expo install expo@^58 --fix`.

## D3. Toolchain

| Tool | Version | Why |
| --- | --- | --- |
| Node | 24.21.0 LTS (`.nvmrc`) | Expo 57+ requires Node ≥ 22.13; machine had Node 20 (EOL). 24.22.x was too new. |
| .NET SDK | 10.0.401 (runtime 10.0.12) (`apps/api/global.json`) | .NET 10 LTS. 10.0.13 / SDK 10.0.402 was too new. Installed to `~/.dotnet` with the official `dotnet-install.sh` (no sudo). |
| JDK | 17 (existing) | Required by the Android Gradle Plugin used by RN 0.86. |

## D4. No JS workspaces at the repo root

`apps/mobile` owns its `node_modules` and lockfile; the root `package.json` only holds
convenience scripts. npm workspace hoisting is a known source of broken Gradle paths and
duplicate native modules in React Native apps, and the API is .NET, so a JS workspace
gains nothing today. If a shared TS package is needed later (e.g. shared zod schemas),
revisit.

## D5. Continuous Native Generation

`apps/mobile/android/` is generated by `expo prebuild` and is git-ignored. Native changes
go through `app.json`, config plugins, or the local Expo module in
`apps/mobile/modules/` (Phase 4). The brief's `/native` folder is therefore
`apps/mobile/modules/sms-reader`, as the brief itself allows ("inside the mobile app's
modules folder").

## D6. Install scripts

npm 11 blocks dependency install scripts until approved. Two were denied (recorded in
`allowScripts` in `apps/mobile/package.json`):
- `unrs-resolver`: a fallback downloader; the native binding already ships as an optional dependency.
- `fsevents`: ships a prebuilt binary; the script is only a node-gyp fallback.

## D7. Test runner on .NET 10

.NET 10's `dotnet test` no longer runs VSTest for xUnit v3 projects. The API opts in to
Microsoft.Testing.Platform in `apps/api/global.json`, so `Microsoft.NET.Test.Sdk` and
`xunit.runner.visualstudio` are not needed.

## D8. Code analysis

`AnalysisLevel=latest-recommended` + `TreatWarningsAsErrors`. Rule CA1707 (no underscores
in member names) applies to tests too, so test names are PascalCase
(`ParseKeepsEqualsSignsInsideValue`) rather than `Parse_Keeps_...`. No rules are disabled.

## D9. `.env` loading

A ~60-line in-repo loader (`Configuration/DotEnv.cs`) instead of a NuGet package: it walks
up from the working directory, never overrides real environment variables, and never logs
values. Precedence: real environment → `.env` → `dotnet user-secrets`.

## D10. Docker is not installed

Testcontainers (Phase 7 API integration tests) needs a Docker-compatible runtime.
To be resolved in Phase 7 (Docker Desktop, Colima or OrbStack); flagged to the user.

## D11. SMS dates

`occurredAt` is the SMS receive timestamp, not a date parsed from the body: banks send alerts within
seconds, and body dates vary by bank and usually omit the time.

## D12. Dedupe details

- `dedupeHash = sha256(upiRef)` if present, else `sha256(amount|last4|minuteBucket)` (as specified). Manual
  entries hash a random id, so they never collide.
- Window rule (±3 min, same amount and direction): same last4 → duplicate; different last4 → not; otherwise a
  loose merchant match, or an SMS vs app notification pair (notifications rarely carry the account) → duplicate.
- Two different references are always two payments.
- On a window match the existing row is enriched (upiRef, last4, balance) and keeps its id and hash.

## D13. What counts as spend

Debits that are not excluded ("Not an expense") and not in a fixed category (Rent & EMI; those are budgeted
via fixed expenses). Credits never reduce spend. IMPS/NEFT debits and phone-number VPAs default to
"Transfers to people"; credits are "Other".

## D14. Budget rounding and freezing

`todayBudget` is rounded half-up to the paisa (5000000/30 → 166667 = ₹1,666.67). It is frozen per IST date in
`daily_budgets` on first access. Because it only depends on spending *before* today, freezing at 14:00 gives
the same number as 00:00. Changing the profile clears today's and future frozen budgets.

## D15. Live SMS while the app is closed

Native receivers always enqueue first, then either emit an event (JS running) or start a headless JS task.
If Android blocks a background service start, the queue is drained at the next app start. Raw text lives
only in that app-private queue until parsed.

## D16. SMS permissions and Play Store

READ_SMS/RECEIVE_SMS are restricted on Google Play (only default SMS apps or approved exceptions). This
build is intended for sideloading/personal use; a Play release would need a permissions declaration or
notification-only mode.

## D17. Repository tests use node:sqlite

Repositories depend on a small `SqlDb` interface matching expo-sqlite. Tests use Node 24's built-in
`node:sqlite`, so real SQL (constraints, ON CONFLICT, LIKE escapes) is exercised without a native module.
